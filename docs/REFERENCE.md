# Urban Planning — full reference

A free browser-based planning workspace under active development. Search US ZIP codes, cities, street addresses, or a map location; open prepared areas or use a free account to prepare an eligible Census ZCTA. Real bundles for **85004 and 60601** and the smaller Roosevelt Row reference area support inspecting buildings and streets, editing proposals, comparing transparent estimates, saving projects, and publishing read-only snapshots.

**This is not the completed national product.** The original [product requirements](<../Urban Planning — Product Requirements.md>) remain the target. The [implementation status ledger](IMPLEMENTATION_STATUS.md) distinguishes working functionality from partial implementations, missing integrations, and external prerequisites.

The app is **100% free**, with no paid feature/data gates or paid processing priority. Visitors can explore and edit anonymously; free accounts enable durable work, uploads, collaboration, AI when implemented, and heavy processing. Fair-use queues and temporary rate limits are permitted. Any later app pricing or custom implementations such as Chicago or Brooklyn remain undecided. Operator-funded data licenses do not imply a customer charge. See the [full implementation plan](IMPLEMENTATION_PLAN.md) for architecture, dependencies, and measurable completion gates.

The initial total operating ceiling is **$300/month**, adjustable by the platform administrator. Private controls now include fixed-cost reserves, a safety margin, a manual cost ledger, atomic job reservations, reconciliation, and audited changes. Forecasts, billing feeds, and provider/cloud spending controls remain pending; no paid provider is enabled. Integrated costly work can be held while cached/basic exploration continues. Unconnected charges and billing delays prevent an absolute billing guarantee.

The [workforce workbench](WORKFORCE.md) connects regional car/walk routing with sourced education/occupation evidence, durable project jobs, saved captures, frozen public views and exports. Runs require an operator-configured source pack, routing service and declared capacity; the worker starts disabled. Actual Arizona source and native-routing checks are available. Transit, nationwide coverage and production operations remain unfinished. [Routing operations](ROUTING.md) describe the pinned native engine and resource bounds.

The [jobs accessibility workbench](ACCESSIBILITY.md) counts captured primary jobs reachable from a chosen origin in 15/30/45 modeled minutes by car or on foot. It retains the complete Arizona workplace inventory, independent mode captures, explicit unresolved quantities, and frozen saved/public/export evidence. Its bounded worker starts disabled until the operator configures sources and existing capacity. Transit and changes caused by authored scenario networks remain pending.

The [flood evidence workbench](FLOOD.md) attaches an operator-prepared FEMA effective map and screens baseline/proposal building footprints against the same retained source. Building edits update known home exposure, while missing home quantities and undetermined map coverage remain explicit. Guests can attach public evidence for free; account saves, history, public snapshots and exports preserve the selected capture and calculation method. Both retained 85004 and 60601 captures pass independent local geometry/count audits under method 1.1, with local cold model calculations around a quarter second. Older scenarios retain method 1.0 unless explicitly updated; undo and published reports preserve the original results. National preparation, representative performance testing and independent mapping/building validation remain pending.

The [geographic import workbench](GIS_RUNTIME.md) supports GeoJSON, zipped shapefiles and DXF footprints through private queued inspection, explicit coordinate placement and field mapping, source-rights review, and an exact preview before one undoable apply. Unknown building quantities remain unknown through calculations and reports. Matched updates require unambiguous identifiers. Shapefile exports retain full geometry, status flags and exact JSON sidecars. The bounded offline converter is disabled until its fixed processing capacity and budget are configured; the app remains free.

A [native traffic workbench](TRAFFIC_RUNTIME.md) retains real FHWA counts and runs bounded paired SUMO experiments on a prepared ZIP-plus-buffer graph. Saved project configurations, scoped jobs, capacity admission and captured results are connected. An optional [Census commute preparation](TRAFFIC_COMMUTE.md) retains source estimates, supported routes and every unresolved quantity, with searchable trip accounting and complete CSV exports. Coverage remains partial; this is not an empirically calibrated traffic forecast.

## Run locally

Requirements: Node.js 22.13 or later, Corepack, and a browser supporting WebGL2 for the 3D view. Docker is optional for the local PostgreSQL/PostGIS adapter and required for the opt-in offline GIS converter.

```bash
corepack pnpm install
corepack pnpm dev
```

Open `http://localhost:5173`. Vite serves the frontend and proxies `/api` to Fastify on port 3001. The default API host is loopback. Prepared bundles are included at `public/data/phoenix.json`, `public/data/zcta-85004-2020.json`, and `public/data/zcta-60601-2020.json`. An official ACS demographic cache is also included; exploring these sources requires no paid provider key.

Without `DATABASE_URL`, the development API persists scoped records in `.local/api-state.json.sqlite`. Existing `.local/api-state.json` data is migrated with full-state verification and preserved unchanged. Stop older API processes before migration; the preserved JSON is no longer updated after cutover. See [storage and recovery](STORAGE.md). Browser drafts persist separately in IndexedDB. Navigation protection remains active while a draft is unapplied or a browser write is pending or failed; wait for “Browser draft saved” before relying on a reload. The development adapter refuses production mode. The API loads `.env` when present; existing process variables take precedence. Vite reads its own `.env` variables normally. Keep private keys out of `VITE_` variables, which are bundled for browsers.

Browser drafts use IndexedDB to retain their captured source data with the project. Older local-storage drafts require an explicit recovery choice because their original source data was not saved. Cloud projects and complete project exports also retain the captured baseline; refreshing the catalog does not update an existing project's evidence.

Project home separates **On this browser** drafts from saved account projects and lets signed-in users switch workspaces. Saved browser drafts retain their account connection, but recheck server permissions before showing the map or allowing edits. A successful authenticated save supplies the current permission result before the draft becomes account-linked, preserving an in-progress sharing or export dialog; restored browser data never supplies that grant. First save adopts the server's new project ID in one browser transaction, retaining pending edits and selection while replacing the anonymous entry. A failed or conflicting browser write preserves the original draft. Sign-out, workspace mismatch, and revoked/unverified access show a recovery screen; authorized project lists control which saved draft names appear. Browser data remains on the device: this interface gate is not encryption or remote deletion. Restoring a complete project export creates a separate copy, preserving newer local edits and their history. When another person saves a newer version, keep your edits as a separate browser copy before reopening it. Browser storage is device/origin-specific and is not a substitute for account saves or downloaded backups.

The private [operating-budget dashboard](BUDGET.md) starts at **$300/month**, with an editable ceiling, a $30 safety buffer, fixed-cost reserves, and an audited manual cost ledger. Explicit cost reviews retain unresolved expenses and provide low/expected/high spending scenarios, freshness checks and complete history. Stale evidence pauses new costly work without releasing unknown charges. Costly processing starts paused. Automatic billing feeds are not implemented; optional SMTP delivery requires separate operator configuration and budget admission. These controls cannot enforce charges outside integrated operations. Register your own free account and follow [administrator setup](../apps/api/README.md#administrator-setup) to enable the dashboard for your verified account ID. Ordinary project owners do not receive platform administrator access.

## Useful working flows

1. **Choose a place without an account.** Search a ZIP, city, address, or map location. City/address results locate a containing ZCTA; they do not create a citywide study. Open an existing prepared area, inspect buildings and source coverage, switch 3D/2D views, and read Census community context. Satellite view uses Esri World Imagery by default; optionally set `VITE_MAPTILER_KEY` to use your licensed MapTiler imagery.
2. **Create an alternative.** Option A starts unchanged from the locked baseline. In **Build**, choose **Place a preset** or **Draw a footprint**. The library includes distinct townhome and hospital presets. Review **Program & massing** and **Footprint** together: add courtyards or separate wings, move/rotate/resize the geometry, allocate mixed-use floor area, and enter homes/jobs and trip/parking overrides with explicit denominators. **Apply building** saves the draft as one reversible edit; **Discard draft** retains the current alternative. Geometry changes do not silently rescale entered quantities. Or open the street list to **Draw a street**. Use the 2D map or exact coordinates to place and move path points; an existing street also offers **Reshape street path** and **Remove street**. **Apply street** commits a valid draft, while **Discard draft** leaves the proposal unchanged. Applied edits support undo/redo, branching, and comparison and persist in the browser draft. **Scenario details** lets you name the option and write proposal notes as one reversible edit. **Before / after** reveals the locked baseline and proposal through a draggable, keyboard-accessible divider on the same camera; the scorecard continues to describe the proposal.
3. **Plan parcels and blocks.** Open **Parcels** to draw, reshape, or remove boundaries in 2D, with exact-coordinate entry, holes, and separate land components. **Subdivide boundary** previews a straight cut; **Assemble boundaries** unions selected lots of the same kind without filling gaps. Apply the preview as one undoable edit. The inspector shows land area, whole-building matches, FAR, coverage, and baseline-building context within the selected boundary.
4. **Understand a number.** Select a scorecard metric to read the formula, assumptions, baseline, change, geography, method version, and source records. Inferred attributes and illustrative coefficients remain labeled.
5. **Save for later.** Create a free account or sign in, open the project menu, save the project, and reopen it from saved projects. There is no payment flow or paid feature tier.
6. **Review with a team.** Open **Team** on a saved project to add an existing free account as an owner, editor, commenter, or viewer. The recipient switches to the shared workspace from project home and sees only authorized projects. Open **Review**, **Discuss this building**, or **Discuss this metric** to start revision-bound threads, reply, resolve discussions, and navigate map pins. Location comments support both map clicks and typed coordinates.
7. **Share a frozen proposal.** Publish a snapshot and open `/shared/<id>`. The public view uses the captured place, scenario, and results rather than the current mutable project. Visitors can inspect features and evidence without editing. Choose comments, location pins, proposal responses, and up to five short survey questions before publishing. Free signed-in accounts can respond to that frozen proposal. Open **Feedback** in the project workspace to review responses, close or reopen collection, record moderation decisions, and download a PDF/CSV engagement report.
8. **Export results.** Browser exports include scorecard CSV, GeoJSON, project JSON, a printable HTML report, and a captured PNG. Authenticated API exports include actual PDF, Word, XLSX, CSV, GeoJSON, and full records. PDF and Word include a decision brief, matched before/after plan maps from the saved geometry, proposal notes, detailed scorecards, assumptions, methods, and sources. Map figures use the same projection and include hashes and attribution. Applied street and parcel changes flow into proposal exports; GeoJSON retains full parcel holes/components, source references, and lineage alongside road geometry and attribute sources. Unapplied geometry drafts are excluded from saved results and must be applied or discarded before export. The saved-project GIS tab also queues a Shapefile ZIP with exact JSON sidecars when fixed processing capacity is enabled. When fixed media capacity is configured, **High-resolution still · PNG** produces an exact 1080p or 4K composition and **Tour fly-through · MP4** renders the full saved tour at 720p or 1080p/30 fps. Preview the frozen scene, choose timing and download full transcripts, source details and frame receipts. Video currently has no audio; see [media setup and limits](MEDIA.md).
9. **Tell the story in a meeting.** Open **Present** for a quick overview, then **Edit tour** to create a saved sequence. Capture the current map view or enter precise camera coordinates, write callouts and optional narration transcripts, attach up to six revision-matched measures per stop, and reorder the outline. **Save tour** commits one reversible scenario edit. Use **Previous/Next**, arrow keys, timed playback, and fullscreen to present; reduced-motion preferences replace flights with immediate camera changes. Published snapshots offer **Watch guided tour** and keep their original tour after later private edits. Device read-aloud is optional and depends on available local voices; the complete text remains readable. PDF/Word reports include the authored outline, and XLSX/complete JSON exports retain it. Use the separate **Tour fly-through · MP4** export for a captioned movie; local read-aloud is not recorded as audio.
10. **Prepare an eligible new area.** Sign in to a free account and request the selected ZCTA. The durable job reports progress, source warnings, cancellation, and explicit retry options. Area/feature limits may require regional preprocessing; a rejected or incomplete preparation is not presented as a complete map.
11. **Model people, jobs and household vehicles.** Open **People**, then **Set up People controls**. Choose absolute counts or percentages of a fixed year-zero reference, inspect the resulting totals, and apply the whole draft as one undoable edit. Under **Neighborhoods**, paint/erase an area, enter exact rings, or use an industrial/warehouse footprint; holes and disconnected components are preserved. **Keep area in draft** previews local exceptions before **Apply People controls** updates the proposal. The preset menu offers +25% population, a sourced ten-year projection, and documented workplace-job removal. **Demand** requires explicit method review before enabling proportional responses.
12. **Screen retail opportunities.** Open **Economy → Retail gaps → Set up retail evidence**. Declare a matching annual geography, dollar basis and category classification, add your study citations and permitted uses, then enter category demand and local establishment sales. Test explicit added sales capacity, capture and displacement, inspect the calculation, and **Apply retail study** as one undoable edit. Missing and suppressed values stay separate from zero. Private studies can be saved and exported; public snapshots require an explicit public-redistribution declaration for every retained retail source. Category CSV, project/GIS metadata, PDF/Word appendices and XLSX sheets retain the inputs and results.
13. **Review a fiscal proposal.** Open **Economy → Incentives → Open fiscal workbench**. Record jurisdiction applicability, compatible assessed values, service allocations and nine cited coefficients in a profile. Create a separate browser or saved fiscal study; the original project and its history stay intact. Compare the baseline, the same development without an offer, and development with a grant/added-value abatement. Save paired sensitivity cases, inspect time-zero and annual cash flows, and apply the offer/cases as one undoable edit. Reusable browser/workspace profiles keep immutable versions. Changed inputs need renewed review. Fiscal CSV, workbook, report and public-snapshot evidence retain the exact study; source export and publication permissions are separate. These are planning estimates, not a claim that an incentive caused development. See [fiscal methods and scope](FISCAL.md).

13. **See who can reach a site.** Open **Economy → Readiness → Open workforce workbench**, select a site and car/walking mode, then run on a free saved project when the operator has enabled routing. Inspect separate education and occupation panels at 15/30/45 minutes, source coverage and conditional uncertainty. Save a completed capture as one reversible scenario edit, or download the full retained routing evidence. Public views and report exports retain saved results; imported copies are explicitly labeled unverified. See [workforce setup and limitations](WORKFORCE.md).

Tour drafts protect navigation until saved or discarded. Read-only roles and the locked baseline can present but cannot save a tour. Up to 24 saved stops retain their title, callout, optional narration, view and camera; they reference metric IDs rather than copying numbers. Unknown or unavailable metrics remain explicit, and methods, source types/vintages, coverage and model limitations remain accessible while presenting. Team-authored narrative should be reviewed after changing a proposal. Tours upgrade a project to format 4 while retaining legacy source hashes and undo/redo history; older projects are not rewritten merely by opening them.

Narration uses only voices the browser identifies as local through [`SpeechSynthesisVoice.localService`](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService). It starts only on an explicit read-aloud action and stops on navigation, closing, or hiding the page. No runtime AI, paid speech service, generated narration file, or external voice endpoint is enabled. Fullscreen uses the browser’s [fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen), with an in-window presentation retained if the request is unavailable or denied.

New projects are private to their creator and explicit project members; workspace owners retain disclosed administrative access. Existing workspace-shared projects preserve access until the first member change captures their effective membership. New sharing requires a verified inviter, a pending invitation, and explicit acceptance by the matching verified recipient. Account security supports email verification, password recovery and password changes with revocation of old sessions. External email is disabled until its sender, encrypted outbox keys, SMTP transport and operating budget are configured; see the [account lifecycle contract](../apps/api/README.md#email-verification-recovery-and-invitations). Internal threads and map pins are excluded from public snapshots and map image captures. **Saved records · JSON** exports one consistent saved version including project/source data, sharing, audit, threads/replies, and public feedback. Saved server exports reject stale versions instead of mixing revisions.

Feedback summaries count the latest vote and survey from each participating account; individual comments are counted separately. Pending review is included and disclosed. Excluded or replaced responses remain in the complete project records. These are self-selected account responses, with no verified-resident or representative-poll claim. Survey questions are frozen with each publication; publish a new snapshot to ask a different survey.

Street authoring supports up to 500 points per changed path and validates entire segments against the exact study boundary, including holes and separate components. Existing captured paths remain usable for settings-only edits. New streets start with editable, explicitly estimated two-lane, 25 mph settings and no traffic count. Reshaping in the street editor clears a retained AADT and records user-authored geometry separately from the original source. Road, lane, and bike-lane lengths update; snapping nearby points only aligns geometry. Connected intersection topology, rerouting, congestion/LOS, calibrated traffic response, and transit authoring remain pending.

The import wizard supports separate **building footprints, parcels, and blocks**. Parcel/block GeoJSON preserves Polygon/MultiPolygon holes and components, uploaded source details, and source feature references. Preview checks the target alternative; committing requires review acknowledgment and creates one undo step. Parcel and block boundaries are planning geometry, not verified cadastral lots, ownership records, or zoning approvals. The current workbench adds explicit attribute mapping, Shapefile ZIP and closed-footprint DXF support with reviewed coordinate placement. Authoritative parcel/zoning providers, scanned site-plan interpretation and traffic-count imports remain pending.

Parcels of the same kind may share edges but cannot overlap land area; blocks may contain or overlap parcels without inflating parcel metrics. Each ring allows 500 points plus its closure, each feature 5,000 total vertices, and each scenario 5,000 parcel/block features. Overlap validation uses a bounded 50,000-candidate budget; an import additionally allows 50,000 total vertices. Excess complexity is rejected without simplifying or discarding geometry. Subdivision preserves original land and holes, rejects no-cut/sliver results, and creates a separate lot for each resulting connected component. Assembly may explicitly retain a disconnected MultiPolygon.

FAR uses wholly contained building programs. A building crossing the selected boundary leaves its complete floor area, homes, and jobs unresolved; coverage still uses the exact clipped footprint union. Blocks are excluded from aggregate parcel denominators. Aggregate baseline and proposal metrics use their own parcel sets: absent baseline parcels remain unavailable, not zero. The inspector's separate baseline comparison uses the same selected proposal boundary on both sides and labels that distinction. Inferred building attributes remain estimates.

Parcel-bearing projects use **project format 2** so older clients reject them rather than discard unknown geometry. Unchanged legacy projects remain readable as format 1; captured baseline objects and hashes are preserved. Format 2 remains after undo/restore, and the server rejects a downgrade. These format versions are separate from the baseline hash/version and storage-envelope versions.

People controls distinguish physical building capacity, modeled effective activity and published historical estimates. A global target describes the study area before neighborhood exceptions. Each disjoint area replaces its own allocated count; the app does not silently redistribute people or jobs elsewhere. Building-weighted allocation uses clipped footprint shares; uniform-area allocation must be selected explicitly. Missing weights remain unallocated. Targets apply at the selected horizon without a second growth factor. Count controls do not resize buildings or change entered homes, floor area, parking supply or property values.

Household vehicles available are distinct from registered fleet, daily traffic, trips and illustrative map agents. Fresh matching-ZCTA captures can retain an independently versioned ACS B25046 supplement. For an existing saved project, **Check prepared Census vehicle reference** reads the local official cache and adds a frozen reference only to the draft; the original source bundle remains unchanged. Entered references retain their year, universe and source description. No regional forecast is built in: the ten-year preset requires a cited projection, and applying a wider-region ratio locally is labeled an author assumption. A closure changes documented area employment while retaining the building, without inventing migration or indirect layoffs.

Proportional demand responses start off. Reviewed population sensitivity can change residential demand; employment sensitivity applies only to eligible office/industrial/warehouse demand. Household-stock sensitivity replaces the residential population factor instead of multiplying both. A reviewed zero target yields zero eligible demand; positive targets with missing or zero denominators remain unavailable. Employment-linked parking cancels horizon growth once so a fixed job count does not lose parking merely because the horizon changes. These sensitivities are not a calibrated transport model. Mode shares and the legacy trip-demand coefficient remain separately labeled assumptions.

Activity controls upgrade a project to **format 5** and use **model 0.5.0**. Exact applied controls and area geometry persist through account saves, history, frozen public inspection, JSON/GIS, and PDF/Word/XLSX inventories. Each alternative allows 100 disjoint areas, 500 points per ring, 5,000 vertices per area and 50,000 total vertices. Brush radii range from 5 to 1,000 meters; completed strokes are bounded and computed in a cancellable worker. Complexity is rejected explicitly rather than silently simplified. Draft totals calculate off the main thread; navigation and export protect unapplied changes.

## Geography, preparation, and Census data

Retail studies use supplied evidence; no retail data provider is connected. A positive demand–sales gap is a screening signal, not observed resident spending outside the area. Categories must be mutually exclusive and comparable: industry sales and commodity expenditures cannot be mixed without a documented mapping. Source declarations are user attestations, not independent license verification. The study does not automatically change building capacity, activity, traffic, prices or fiscal revenue. Changing the scenario horizon withholds proposal retail results until the study is reviewed for that horizon; captured reference amounts remain available. The separate workforce workbench uses captured regional sources and does not infer retail demand. Authoritative retail integrations remain pending.

The Roosevelt Row bundle remains **a rectangular reference extent near 85004**, distinct from the full **2020 Census ZCTA 85004** bundle. The 85004 and 60601 bundles retain their exact Census boundaries. Shared geometry handling preserves multipart components and holes when present; map display, study-area calculations, clipping, and edit constraints use that geometry. Street/building geometry comes from OpenStreetMap; inferred use, floor counts, heights, dwelling/job capacity, and parking retain separate attribute provenance. Complex OSM building/park relations and boundary-crossing footprints are omitted with coverage disclosures, so mapped ways are not a complete building inventory.

National search uses official Census geography and address services. Some postal ZIPs have no ZCTA; geocoded addresses are approximate range matches. Preparation is a **bounded preview**, with a maximum 50 km² study area, 75 km² buffered fetch envelope, 40,000 source features, 500,000 vertices, and a 25 MB source response. Admission permits three new area requests per account per UTC day, ten total attempts per UTC day, one active job, and at least 60 seconds between attempts. Roads use a 100 m fetch buffer before exact boundary clipping; this is not an external-traffic model. Jobs persist their status and recover interruptions. No national tile pipeline or regional routing service is connected.

The public-source preparation flag defaults on in development and off in production. Actual new preparation also requires an explicit fixed-capacity declaration, a current administrator cost review and budget headroom; deployment capacity requires accounted fixed costs. An operator must explicitly enable a bounded production pilot with `NATIONAL_PUBLIC_PREPARATION_ENABLED=true`. Disabling preparation retains search and already prepared places. Public Overpass is not the intended general-launch ingestion backend; regional extracts or dedicated infrastructure and resource controls remain required. See [preparation contracts and limits](../apps/api/README.md#national-place-search-and-bounded-preparation).

The included **2020–2024 ACS five-year cache covers 33,772 ZCTAs** and retains estimates, 90% margins of error, source files, and retrieval metadata. Population, households, housing units, and median household income come directly from published Detailed Tables. Poverty and education percentages use documented Census calculations with approximate margins labeled. Missing or suppressed estimates remain unavailable. Whole-ZCTA statistics are never scaled to a smaller reference area or substituted for mapped housing units. Matching whole-ZCTA population can anchor fiscal resident-service estimates; local cost coefficients remain assumptions and sampling uncertainty is not propagated into fiscal totals.

The cache is prepared once, not downloaded for each visitor:

```bash
corepack pnpm exec tsx scripts/prepare-acs.ts
```

This rebuilds `public/data/acs-2024-zcta.json` from official downloads, reusing `.local/cache/acs-2024/` when present and enforcing a 250 MB transfer cap. The included cache is already usable. Optionally set a free `CENSUS_API_KEY` in the server's `.env` and restart the API to request published Data Profiles instead; never use a `VITE_` variable for this key. If that API fails, the validated Summary File cache remains available with an explicit fallback note. `ACS_SUMMARY_PATH` selects another prepared cache. [Census source and calculation details](../apps/api/src/data/README.md) include the live 85004/60601 verification values.

The separate **2020–2024 ACS household-vehicle cache contains 29,673 ZCTA records** from the official B25046 aggregate, including published 90% margins of error and annotations. It does not derive totals by multiplying top-coded vehicle categories. The current prepared estimates are **7,975 ± 793 for 85004** and **6,149 ± 963 for 60601**; these are historical household-vehicle estimates, not traffic measurements. Missing records remain unavailable. The source file is 22,107,846 bytes, within the 25 MB download cap; the included subset is about 701 KB. See [provider provenance, validation and refresh instructions](../apps/api/src/data/README.md).

## Model methods

The analytical engine implements transparent calculations and optional source-backed evidence interfaces. An interface for routing, economic multipliers, hazard exposure, or safety results is not a connected data source or a validated model. Unavailable metrics are intentionally explicit.

Read [model methods and limitations](../packages/models/METHODOLOGY.md). Fiscal coefficients and trip rates are illustrative until reviewed against local data. No output has yet met the PRD’s consultant-study validation target. The app is not an engineering-grade traffic study or entitlement determination.

The smaller Phoenix reference bundle has a separate source refresh command:

```bash
corepack pnpm data:phoenix
```

It accesses public OSM/Overpass data and rebuilds the reference bundle. Provider availability, source completeness, attribution, and service limits apply. Published snapshots preserve their captured data rather than silently adopting a refresh.
